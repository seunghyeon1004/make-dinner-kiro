Three choices in it go beyond what `product.md` and `testing.md` say (conflicts C1 to C3 in the design), so please answer those before the tasks start.

I ran scratch Makefiles in `/tmp` against this Mac's GNU Make 3.81 (since removed). Points in the design marked "(measured)" come from those runs:

- **`make -n` can run commands.** Make 3.81 runs a recipe line under `-n` if its text contains `$(MAKE)`, and the obvious escape `$$(MAKE)` still contains it. The echo text therefore writes `$` as `$$`, and adds `''` after it when `(` or `{` follows. That `''` is an empty quoted string, so the shell still prints `$(`.
- **A space before the colon changes meaning.** `export : x` is read as an `export` directive and `ifeq : x` as a broken conditional. With the colon attached, dishes named after any of 17 directive words work as plain targets.
- **A comment ending in `\` swallows the next line.** Import reports any line ending in `\` as an error.
- **The worst case holds.** A title with `$(MAKE)`, `$(shell …)`, backticks, `'`, a tab, a newline, U+202E, a lone surrogate and a trailing `\` ran under `make -n` and plain `make`. Exit code was 0 and no canary file was created. The two complete Dinnerfiles in the design (worst case and sunday-roast) are identical to the files Make ran on.
- **Cost of spawning `make`.** About 11 ms per run.

**Checks run:** `tasks-lint.sh` on the new `tasks.md` passed, and `npx prettier --check` on the spec folders passed (`.kiro/` is in `.prettierignore` anyway). No tests were run, since there is no code.

**Conflicts (C1 to C3 need your answer before T1.6, T2.1 and T3.1):**
- **C1, run count:** `testing.md` says 200 runs per property. Your scope asked for a small count, so D2 and P-DF7 use `fcMakeParams()`: 50 runs, overridable with `FC_MAKE_RUNS`. They also do I/O, which `testing.md` doesn't allow in properties. The alternative is 200 runs with a 30 s timeout.
- **C2, metadata format:** `product.md` lists five keys for the `# step` line. I added `title=` and `detail=`, because import may only read comments. Plan titles and dish names are written as JSON strings (`# dish chicken "Roast chicken"`) so trailing spaces and newlines survive.
- **C3, echo line:** `product.md` says `@echo '<title>'`. The spec writes `@echo '<quoted title>' # <step-id>`. Titles needn't be unique, and without the id D2 could only test plans whose titles all differ.
- **C4, Docker:** `node:22-slim` has no `make`, so D2 fails there by design. CI needs GNU Make on `PATH`.

**Other decisions (marked "(decided here)"):**
- **Return types:** `fromDinnerfile` returns `{ plan, options }` rather than a bare `Plan`, so the kitchen and serving time come back with the plan. `toDinnerfile` returns `Result<string, Issue[]>`, because a plan that fails the schema can have step ids that can't be Make targets.
- **Kitchen and serving time:** `# kitchen burners= ovens= cooks=` and `# serve HH:MM` go right after `# plan`. They are comments only, and removing them gives the plain export exactly. A new `ServeTimeSchema` (`00:00` to `23:59`) goes in `schema.ts`.
- **Dish targets:** each dish target lists the dish's last steps (steps no same-dish step waits on). A dish called `dinner` gets a fixed comment instead of a rule. `dinner` is the first real rule, so plain `make -f Dinnerfile` builds the whole plan.
- **What import checks:** only syntax (number form, words, id patterns, strings). Ranges and sanity rules are left to `validatePlan` and `parseKitchen`, which the caller runs. A typo still gets a line number.
- **Numbers:** no sign, no leading zero, at most 6 digits. Metadata keywords are case-sensitive.
- **Tolerance limits:** `.PHONY` content and recipe lines are never read. A dish or `dinner` rule that is present must match exactly; leaving it out is fine. After a broken line, the mismatch checks are skipped so one mistake gives one error.
- **Generators:** they are extended, not narrowed. Free text now draws from a list of hostile tokens, and dish ids include `dinner` and directive words. Every existing property will see these inputs, which may expose bugs in recipe-graph code.
- **Export oracle:** an independent `oracleDinnerfile` with a random style gives P-DF10 (export equals the oracle on every generated plan) and P-DF4 (any tolerated way of writing the file imports the same).
